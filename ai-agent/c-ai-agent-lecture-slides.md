## AI의 진화 단계 — ANI · AGI · SGI

```mermaid
flowchart LR
    A["ANI\nArtificial Narrow Intelligence\n\n특정 작업만 수행\n체스, 번역, 이미지 인식\n\n현재 대부분의 AI"] 
    --> B["AGI\nArtificial General Intelligence\n\n인간 수준의 범용 사고\n새로운 문제 스스로 해결\n\n2~5년 내 도달 예측"]
    --> C["SGI\nSuperintelligence\n\n인간을 초월한 지능\n스스로 더 나은 AI 개발\n\n시점 미정"]

    style A fill:#e8f4f8,stroke:#2196F3
```

<!-- > **발표자 노트:**
> ANI는 Artificial Narrow Intelligence. 지금 우리가 쓰는 ChatGPT, 번역기, 추천 알고리즘이 모두 ANI입니다. 매우 뛰어나지만 딱 그 일만 합니다. AGI는 인간처럼 어떤 문제도 스스로 생각하고 해결하는 AI입니다. SGI는 Superintelligence로, 인간보다 모든 면에서 뛰어난 AI입니다. 오늘 우리가 다룰 AI 에이전트는 ANI와 AGI 사이 어딘가에 위치합니다. 단순 도구에서 목표를 이해하고 스스로 계획하는 방향으로 진화하는 중입니다. -->

```mermaid
flowchart TD
    subgraph 챗봇["챗봇 (기존)"]

    subgraph Agent["AI 에이전트 (현재)"]
        U2[사용자 목표 제시] --> P[목표 분석 및 계획]
        P --> T1[도구 사용\n검색·계산·파일]
```

<!-- > **발표자 노트:**

## AI 에이전트의 4가지 핵심 능력

```mermaid
mindmap
  root((AI 에이전트))
    인식 Perception
      텍스트 이해
      이미지 분석
      데이터 읽기
    추론 Reasoning
      목표 분해
      계획 수립
      의사결정
    행동 Action
      도구 사용
      API 호출
      파일 조작
    기억 Memory
      단기 컨텍스트
      장기 저장
      학습 반영
```

<!-- > **발표자 노트:**
> 에이전트를 이해하는 가장 쉬운 방법은 이 4가지입니다. 인식: 상황을 파악합니다. 추론: 어떻게 할지 계획합니다. 행동: 실제로 실행합니다. 기억: 이전 결과를 기억해서 다음에 활용합니다. 사람이 일하는 방식과 거의 같습니다. -->

## 에이전트 유형 — Single vs Multi

```mermaid
flowchart TB
    subgraph Single["Single Agent"]
        SA[에이전트] --> T1[검색]
        SA --> T2[계산]
        SA --> T3[이메일 발송]
    end

    subgraph Multi["Multi-Agent System"]
        O[오케스트레이터\nAgent] --> A1[리서치 Agent]
        O --> A2[분석 Agent]
        O --> A3[작성 Agent]
        A1 --> R[통합 결과]
        A2 --> R
        A3 --> R
    end

    style Single fill:#e3f2fd,stroke:#1976D2
    style Multi fill:#f3e5f5,stroke:#7B1FA2
```

<!-- > **발표자 노트:**
> Single Agent는 혼자 모든 것을 처리합니다. 간단한 작업에 적합합니다. Multi-Agent는 여러 에이전트가 팀처럼 협력합니다. 한 명이 조사하고, 한 명이 분석하고, 한 명이 보고서를 씁니다. 복잡한 업무일수록 Multi-Agent가 더 효과적입니다. 우리가 팀으로 일하는 것처럼요. -->

## 에이전트가 일하는 방식 — ReAct 루프

```mermaid
flowchart LR
    G[목표 입력] --> Th
    Th[Think\n상황 분석 및 계획] --> Ac[Act\n도구 실행]
    Ac --> Ob[Observe\n결과 관찰]
    Ob -->|목표 미달성| Th
    Ob -->|목표 달성| Re[결과 반환]

    style G fill:#FFF9C4
    style Th fill:#E3F2FD
    style Ac fill:#E8F5E9
    style Ob fill:#FBE9E7
    style Re fill:#F3E5F5
```

**ReAct = Reasoning + Acting** 

<!-- > **발표자 노트:**
> ReAct는 AI 에이전트가 작동하는 핵심 원리입니다. 생각하고(Think), 행동하고(Act), 결과를 보고(Observe), 다시 생각합니다. 이 루프가 목표를 달성할 때까지 반복됩니다. 사람이 문제를 해결할 때와 동일한 방식입니다. -->

## n8n vs Make vs Zapier — 한눈 비교

| 항목 | n8n | Make | Zapier |
|------|-----|------|--------|
| **셀프호스팅** | 가능 (핵심 강점) | 불가 | 불가 |
| **AI 에이전트 기능** | LangChain 네이티브 통합 (70+ AI 노드) | Maia AI 어시스턴트 | Zapier Agents |
| **시각적 편집** | 중간 | 최고 | 중간 |
| **연동 앱 수** | 400+ | 1,500+ | 8,000+ |
| **가격 (월)** | 셀프호스팅 시 무료 | $9~ | $19.99~ |
| **기술 난이도** | 중~고 | 낮~중 | 낮 |
| **데이터 주권** | 완전 통제 가능 | 클라우드 저장 | 클라우드 저장 |
| **보안 환경 적합성** | 높음 | 낮음 | 낮음 |

<!-- > **발표자 노트:**
> 보안 환경에서 가장 중요한 기준은 "데이터가 어디에 저장되는가"입니다. Make와 Zapier는 클라우드 기반이라 데이터가 외부 서버를 거칩니다. n8n은 사내 서버에 직접 설치할 수 있어서 데이터가 외부로 나가지 않습니다. 이것이 우리 환경에서 n8n이 가장 현실적인 선택인 이유입니다. -->
